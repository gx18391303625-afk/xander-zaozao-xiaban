# 广告表现诊断与可复盘行动

用于“为什么变差”“是否加预算”“现在哪一步最值得做”和一次具体广告实验。用现有报告、经济计算与行动账本完成短诊断；完整建案仍走原策略合同。

## 先计算变化，再寻找解释

由 AI 取报告并整理 `xander_review_ad_performance` 输入，不让用户手填结构。按工具实际 schema 使用 `scope`、每个实体的 `rows`、`current` 和可选 `baseline`；标明真实提供数据或 `simulation`。它复算输入，不独立认证来源，不自动选择最优竞价或执行。不可用时可按下述恒等式复算并说明方式。

最小输入可参考 [模拟报表示例](../../../examples/ad-performance-review.json)；示例不是账户事实。

- 当前与基准分别保留报表ID、窗口、时区、对象ID、广告产品、计费、点击/浏览归因、归因窗口和商品销售范围。只合并不重叠的原生行，不能把 campaign、target、search term 与 placement 行相加。
- SP/SB/Display 分开解释，混合归因或不同目标不按一个ROAS榜单排序。完整日与部分日、成熟与未成熟窗口分开。报表生成中、字段缺失和真实零不同。
- 用分子分母重算指标，不平均行级比率。工具 `metrics.orders` 承载口径已核的购买/订单数，不放零售件数；购买可多件，库存消耗用件数。

同一组匹配的点击、购买、销售和花费，且分母为正时：

```text
CPC = spend / clicks
CVR = orders / clicks
AOV = attributed_sales / orders
ACoS = spend / attributed_sales = CPC / (CVR × AOV)
ACoS倍率 = CPC倍率 / (CVR倍率 × AOV倍率)
```

工具变化分解仅用于 `CPC + CLICK` 基准；CPM/vCPM、浏览或混合归因及认知目标按对应覆盖、可见性、频次等指标判断，不套CPC效率结论。这是算术分解，不证明因果。零或未知分母时相关比率/倍率不可算，不用0或无限值补齐。组合权重、归因回填、价格和流量质量都可能改变汇总值；只在可比且成熟时解释变化分解。

## 用证据区分原因

| 观察 | 最有区分力的下一项证据 | 决策边界 |
|---|---|---|
| 展示/流量下降 | SKU可买性、Featured Offer、预算耗尽时间、目标/否定状态、报告覆盖 | 先排资格与数据问题；加bid不能修复失去Offer |
| CPC升高 | 有效bid、竞价策略、版位/受众调整与流量组合 | 平均CPC不是基础bid；经济承受CPC不是自动调价公式 |
| CVR降低或相关词无单 | 成熟搜索词/商品数据及同期价格、促销、PDP、配送、库存、评价 | 可能是Offer问题；不按固定点击数批量否词 |
| ACoS好但经营变差 | 匹配贡献、零售总销量/销售、退货促销、品牌防御与获客组合 | 归因销售不是增量；低ACoS不等于盈利或值得扩量 |
| 预算早耗尽 | 在预算时的成熟效果、实际time-in-budget/耗尽记录、库存与销售窗口 | 耗尽证明约束，不证明追加花费有同样回报 |

证据不足时给最能排除候选根因的一项取证，说明它会改变哪个决定。“建议优化Listing/竞价”不是已完成诊断。

## 把经营约束带进建议

- `economics.contributionBeforeAds` 与 `profitFloor` 是匹配本行归因销售和窗口的总额，不是每单金额。扣本行花费形成描述性广告后贡献；共享或halo销售未映射不能乘本ASIN毛利率冒充利润。需要时先用 `xander_calc_ad_economics` 计算并按可审计数量归一到期间总额。
- 利润底线和风险缓冲分别保留。提高预算需有受限且值得获取的流量证据、当前经济承受额和库存现金支持；历史平均回报不保证边际回报。工具的人工复核候选不是“已建议执行”。
- `inventory.availableUnits` 使用已扣一次保留/安全库存的当前可售件数；`dailyUnitDemand` 使用同范围总零售件销量，不用广告订单数。入库未可售不加现货。扩量、改价或季节变化后重算需求情景，与补货可售日和剩余销售窗口比较。
- 零售输入必须同商品同期间。`rowSpendToRetailSalesPct` 仅是本行花费/所供零售销售，不是全广告TACoS；保留 `scope.entityType` 和行ID对应的原生粒度，同一零售分母不能在多个活动/目标行重复加总。全广告TACoS需另取同范围全部广告花费及一次计入的零售销售。
- 改价/图文/促销等实际变化记录进 `changes`。预算受限用实际证据，不能用花费接近预算自行充当已核耗尽。
- 保留不动和减少暴露选项。无精确成本仍可报告已验证的资格/浪费事实与有限取证，不编成本、不为窄结论生成完整策略包。

## 广告层级与实验单位

SP活动管理预算、定向类型、竞价策略及适用版位调整；广告组组织相关商品和目标。拆组不产生独立预算，拆活动也不保证随机流量或双倍触达。默认bid与显式目标bid分开核，改默认不假定全部跟随；活动级否定影响其组，正向高bid不绕过否定。其他产品按实际版本核，不能照搬SP层级。

试验先写业务问题、真实可编辑变量、实验单位、主要KPI、成本/质量保护指标和停止条件。点击目标可看CTR，销售/利润目标还需购买与贡献，不凭CTR选利润赢家。共享ASIN的PDP主图变化会影响多组广告及落地体验，复制广告不是对照；系统自动选创意或不同版位分配也不是随机A/B。

尽量保留同期可比对照和其余条件，检查版位/受众/商品权重。同期改价、促销、库存、图文、bid或预算时记录混杂，不强行归因单一动作。固定2–14天、20/30点击、每天选最高CTR不保证充分样本。风险停止与统计胜出分开；按归因回填、样本信息和报告可得性定复盘，不机械等日历。

## 输出与接续

先给一句判断和关键数值，再给最多三项人工复核待办，不凑数。每项有对象ID、证据/不确定性、具体下一步、预期观察、成本或库存边界和最早可解释复盘条件。先区分事实与候选根因，再决定 `KEEP`、`OBSERVE`、取证、跨模块交接或准备精确提案。

精确标量动作沿原 prepare/批准/execute/回读流程，保留相关经济和范围检查；本计算不授权执行。完整方案才生成完整策略包。

保存时复用 [诊断与行动复盘](../../xander-operations/references/diagnostic-action-review.md)，不建第二套状态机。手动和工具操作都记实际时间、证据、用户明示理由、预期与取舍，未知不编造。复盘分清平台状态回读、经营结果观察、因果仍未知；写了建议或日期已到不代表监控已运行。

## 当前官方核验要点（2026-11-06）

这是带日期的起点，具体账户与功能仍按实际官方帮助核；旧课程情景不能覆盖新规则。

- [竞价策略，2026-09-28](https://advertising.amazon.com/help/GCU2BUWJH2W3A8Z7)：dynamic up/down各版位最多提高/降低100%，旧顶部100其他50不沿用。基础1、版位+50%时静态1.5，再按动态上限可达3；其他适用调整另核，不能拿平均CPC当上限。
- [预算，2026-11-02](https://advertising.amazon.com/help/GTGPQGUXNCTHE2DS)：日预算按月平均，默认高流量日可上浮100%，可选25%，不是单日硬cap。旧预算指南仍有25%措辞，操作以当前Help与账户值为准；修改预算、规则与其他限额另核。
- [归因，2026-10-20](https://advertising.amazon.com/help/GX7KDKHMWQYMJ385)：SP seller通常7日点击，vendor/author14日；SB/Display及浏览归因另核。按交互日期回填，归因销售与零售销售不同，购买可含多件。
- [Featured Offer，2026-10-16](https://advertising.amazon.com/help/GYVDGT5WNNW23LJ5)：资格不等于持有；SP/商品型Display可在Delivering状态仍无展示，SB在其他卖家持有且商品可买时可继续。状态不能证明实际投放，按SKU核。
- [SP站外投放，2026-10-12](https://advertising.amazon.com/help/GYTD2Z3SYMAAMVXA)：产品名不保证Amazon-only，核Limit reach to Amazon。站内版位加价不适用站外，动态/规则竞价仍适用；保留站内外原生标签。
- [SB视频当前指南](https://advertising.amazon.com/library/guides/getting-started-with-sponsored-brands-video)：存在theme targeting等路径，目标影响落地与计费；执行器枚举不是平台全能力。未支持功能留明确交接，不伪造参数。
- [创意实验原则](https://advertising.amazon.com/library/guides/display-ads-examples)：一次改一项、其他条件一致、按目标测量。上述污染、权重和停止规则是实施判断，不冒充Amazon硬样本门槛。
