- 本技能只出分析，不改账户。需要改动时交给对应技能，并按 [写入安全](../xander-operations/references/write-safety.md) 走“提案 → 用户批准 → 执行 → 回读”；开关只有用户能开。
- 未知数字是 null，不是 0；卖家精灵等第三方字段标 ESTIMATED；模拟结果标 SIMULATED / NOT LIVE。金额统一币种，比率用小数。
- 脚本只在宿主能执行代码时运行（Codex、Claude Code 可以）；否则用透明手算并说明限制。用简洁中文回答。

# 亚马逊竞品作战分析

把买家需求、竞品承诺、体验缺口与我方可证明事实连成可追溯判断。既有项目先定位当前入口、适用数据 SOP、最新竞品清单和采样；复用有效证据，遵守用户数据源/付费上限，不把历史监控清单当成当前攻击授权。

## 档位与路由

用户明确档位/范围优先。否则仅“发布级、可审计、正式立项、完整证据、认证范围核查、同条件量化实测比较”使用深度尽调；其他默认极速实战。单纯提到认证、安全或续航不自动升级。

极速档只取能改变主打法的证据；用户最新确认的当前量产事实作为工作事实，不反复追问或要求第二来源。计划功能/概念图仍是待验证。高风险可形成策略方向，但标志、范围、发布措辞仍待正式核验，不伪装成发布成稿。深度档完成适用的证据账本、评分、反证及发布核验；从极速升级时增量补充，不从头重做。

选择最小模式，按需完整读取对应参考，不默认加载整套资料：

| 模式 | 参考及停止点 |
|---|---|
| 对标锁定：立项包、seed、商品池或锚点 ASIN | [对标锁定](references/benchmark-locking.md)；输出锁定表、覆盖、competitor_lock.json 与刷新条件后停止 |
| 锚点/我方对标/多竞品分析 | [输入与证据](references/input-and-evidence.md)、[竞争框架](references/competitive-framework.md)；只有竞品资料时只给机会假设，不声称我方优势 |
| 我方与竞品的关键词点击率、转化率、购买量或总销量趋势 | [表现对标](references/query-performance-benchmarking.md)；按指定词、对象和期间交付对比与优先检查项，不自动扩展为完整竞品报告或广告调整 |
| 搜索同屏或详情页入口竞争快照 | [入口观察](references/input-and-evidence.md#流量入口观察与交接)；只取指定页面/对象，不重锁组、不全读 VOC、不追加视觉简报 |
| 变化复核 | [增量刷新](references/incremental-refresh.md)；只对实质变化对象重开深拆 |

| 组织竞品分析报告 | [报告契约](references/report-contract.md)，按档位交付 |
| 明确要求拍摄/图片/视频/A+设计交接 | [视觉交接](references/visual-handoff.md)；只看竞品视觉不触发我方简报，最终生图需用户明确请求 |

广告位、排名、搜索词与竞品的联合诊断由广告策略技能主导；本技能只补竞争证据，可复用关键词技能的同屏采样。用户追问差距原因与追赶方案时，将同词表现交接到自然排名、广告位置、历史价格及促销条件的联合诊断；给出有依据的具体候选方案与验证条件，保留竞争解释和因果缺口，不执行调整。立项用选品技能，完整流量词库用关键词技能，标题/五点/ST 成稿用 Listing 技能；不在这里设置预算、出价或否词。

## 执行要点

1. 最低输入为可确认站点及有效 ASIN；对标锁定也可由产品方向/类目 seed 开始。保留用户全部 ASIN 和原顺序，记录变体、币种、目标及输入角色。只有身份/站点无法确认才阻塞；缺我方证据可继续采集并标待验证。
2. 保留 project_id / selection_run_id / candidate_id、事实和证据 ID；经营上下文及 context_id / operating_context_sha256 核对后原样透传，新观察放 competitor_context_updates。不要重算利润底线、路线或补货能力。
3. 页面、图库/A+、VOC、市场估算按会改变结论的需求采集。视觉判断实际看图，VOC 写样本范围；SellerSprite 按当前 schema 优先使用并标估算。每源一次聚焦获取加一次合理替代仍失败就记缺口，不无限换路径。
4. 锁定按参考核对身份、变体、套装与价位，使用统一角色/锁定状态及研究深度。所有评分携带 basis 与 evidence_ids；无效/待定身份不伪造评分。用户已给足对象时仅补缺失角色，不任意扩样。
5. 区分产品、Offer、表达、证据与伪缺口，正面保留对手优势。最终机会必须同时符合高价值需求、竞品缺口、我方可证明、可视化和合规。
6. 深度档评分全部机会；极速档只评分最终 3–5 个候选。输出一个主突破口、最多两个辅助购买理由、必须守住及明确不打，并按报告/视觉契约交付。

## 竞品研究分层

极速档核心对象看完整页面/图库/A+、可用 VOC 和关键第三方字段；标准对象看身份/Offer/核心规格/反证；扫描对象看主图、标题和差异信号，出现改变打法的证据才升级。仅当超过10个 ASIN且用户明确顺序代表排名/优先级时，按1–5核心、6–10标准、11+扫描；普通列表按相关性和证据缺口选深度，绝不改原顺序。排名来源与市场份额另行核实。

## 证据和完成边界

- 动态价格、优惠、评分数、配送、BSR保留观察日期及可比口径；评分数空白不是零，父子共享评分不能直接混比。冲突报价分别保留，不挑有利值。
- 评分数×价格带仅来自用户边界、上游窗口或有样本的市场分布；强信任壁垒留作边界参考，缺币种/有效日期/口径不能靠总分进核心组。
- 页面断货/配送只证明当时状态，不能反推库存量、供应链或销量；Sponsored 密度不能反推 CPC/CVR/竞争人数，目标报表不能还原实际坑位。旧列表与新价格拼接不是同屏证据。
- 区分 OBSERVED / VOC / ESTIMATED / INFERRED / UNKNOWN；我方用户确认可记 OBSERVED / USER-CONFIRMED，不能把竞品陈述或市场常见功能变成我方事实。最新确认修正旧值但保留冲突记录。
- 机会评分不表达胜率；缺关键事实、高风险证据未匹配、我方证明强度低于3只能待验证，硬红线阻断。图片保留 I-ID → O-ID → E-ID/V-ID，未证实主张写待验证；不复制竞品受保护表达。
- 极速档只给一个整体状态：证据足够决定策略为 READY（不是发布授权）；缺口可能改变主打法为 PROVISIONAL；身份/硬红线使核心交付不成立为 BLOCKED。发布前核验不拖住无关策略，不另造第二个发布状态。
- 深度档适用检查未齐或任一核心发布项无法完成为 PROVISIONAL，单项可标待验证/BLOCKED；全部核心交付不成立才整体 BLOCKED。直接发布必须核验当前官方图片/A+规则，未核验至少 PROVISIONAL。
- 证据足以完成用户范围就停止，不机械追加视觉任务、全量词库或整套尽调。

正式锁定用 [score_benchmark_candidates.py](scripts/score_benchmark_candidates.py)；机会排序用 [score_breakthroughs.py](scripts/score_breakthroughs.py)。脚本在本技能 scripts 目录，解析绝对路径运行，不依赖项目当前目录。具体参数和维度分别见对应参考。

## 收尾

先给结论，再给有日期的证据、关键缺口和下一步。用户新确认的我方事实用 `xander_archive_set_fact` 记下（写清来源）；锁定的竞品清单、结论和复查时间用 `xander_archive_note` 记下。规则见 [店铺档案](../xander-operations/references/business-context.md)。
