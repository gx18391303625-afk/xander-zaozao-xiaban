## 使用原则

卖家精灵 MCP 可用时优先使用 MCP；它不可用时再检查用户导出。只有任务依赖已登录网页、扩展或用户明确要求操作现有会话时，才在用户授权范围内使用浏览器或本机界面工具做只读采集。不得请求、读取或保存密码、Cookie、令牌等凭据；不得更改账号设置、投放、Listing 或店铺数据。

优先读取 Amazon 当前页面的直接事实，再用卖家精灵补充估算。界面标签和入口可能随版本变化，以当前可见 UI 为准，不因按钮缺失而反复试探。

每次采集记录：目标站点、页面 URL、ASIN/变体、采集日期、工具/扩展、字段口径和是否为父体聚合。

## MCP 路由

调用前读取当次工具 schema，不凭记忆猜参数。对标锁定常用：

| 目的 | 首选工具 | 边界 |
|---|---|---|
| 类目/节点确认 | `mcp__sellersprite_mcp__product_node` | 避免跨错类目；记录月份 |
| 条件化商品池 | `mcp__sellersprite_mcp__product_research` | 保存全部筛选、排序、页码和停止条件 |
| 批量商品快照 | `mcp__sellersprite_mcp__competitor_lookup` | 单批 ASIN 最多 40；按原顺序稳定分批；显式请求 `rating` 与 `ratings` |
| 单 ASIN 身份/变体/Coupon | `asin_detail_with_coupon_trend` 或 `asin_detail` | 区分父子体、标价、到手价和评分共享口径；批量 `reviews` 空白不是 0 |
| 销量与销售额趋势 | `asin_sales_trend`、`asin_prediction` | 统一标 `ESTIMATED`，不写成卖家后台实绩 |
| BSR/价格/评分历史 | `keepa_info` | 无销量时不自行从 BSR 推导精确销量 |
| 关联竞品发现 | `asin_competitor`、`traffic_listing` | 新对象标 `RESEARCH_ADDED` |
| 流量结构摘要 | `traffic_keyword_stat`、`traffic_source`、`traffic_listing_stat` | 只用于锁定与角色背景；不替代完整词库 |
| 评论/VOC 补充 | `review` | 记录样本、星级、时间和变体，不能外推发生率 |

对标锁定不逐词分页消耗全部流量词额度。完成 `competitor_lock.json` 后，由 `$build-amazon-keyword-library` 使用 `traffic_keyword / traffic_extend` 对锁定范围和全部用户指定 ASIN 做完整采集。

MCP 未连接、无权限或持续失败时依次使用：用户卖家精灵导出 → Amazon 页面 → 当前可靠补充来源。仍缺失时标 `PROVISIONAL`，明确缺少的销量、趋势或流量结构；普通网页搜索不能冒充卖家精灵估算。

## 页面级采集顺序

### 商品详情页

1. 确认 URL 站点、ASIN、选中变体和商品身份。
2. 逐张查看主图、副图、视频、A+ 与比较模块。
3. MCP 不可用且用户授权网页会话时，打开卖家精灵的产品查询或商品数据面板。
4. 采集当前商品的销量/销售额估算、BSR、价格、变体、FBA、上架时间、流量词和趋势。
5. 按需要进入 `历史销量`、`产品卖点`、`产品概要`、`关键词反查` 或 `关联流量`；不进入广告执行或账户修改流程。

### 搜索结果或 Best Sellers 类目页

1. 确认核心词或类目路径与站点。
2. 使用列表数据识别头部、价格带、品牌集中度、新品与直接竞品。
3. 使用 `市场分析` 或同类入口查看样本与分布；样本不足时明确记录。
4. 若支持导出 Top 产品或产品卖点，优先下载结构化文件再分析，避免手工抄录大量行。

### 关键词与流量

1. 从锚点 ASIN 进入关键词反查。
2. 区分自然词、广告词、推荐词和关联流量；不要把词数当成流量规模。
3. 记录关键词的目标站点、时间范围、父子体口径和估算来源。
4. 用关键词判断定位与买家意图，不把第三方关键词估算直接写成 Amazon 官方搜索量。

## 建议字段

按任务需要采集，不追求把所有字段填满：

| 维度 | 字段 | 注意 |
|---|---|---|
| 身份 | ASIN、父/子体、品牌、卖家、配送 | 先确认变体 |
| 表现 | BSR、近 30 天销量、销售额、历史趋势 | 标记第三方估算与周期 |
| Offer | 当前价、Prime 价、Coupon、变体数、卖家数 | 价格是快照 |
| 信任 | 星级 `rating`、评分数 `ratings`、月评新增、Q&A 数、留评率 | 星级与评分数分列；记录 `PARENT / CHILD / VARIATION_SHARED / UNKNOWN` |
| 成本 | FBA 费用、毛利率 | 仅作工具估算；未知成本会扭曲毛利 |
| 生命周期 | 上架时间、近期增长、季节曲线 | 不把相关性当因果 |
| 搜索 | 全部流量词、自然词、广告词、推荐词 | 记录口径；避免重复计数 |
| 产品 | 尺寸、重量、包装尺寸、数量、材料 | 用 Amazon 页面交叉核验 |
| 市场 | 样本数、品牌/卖家/商品数、新品数、价格与评分分布 | 样本不足时降置信度 |

## 导出与质量检查

- 优先保留原始 CSV/XLSX，另建立分析副本；不要覆盖用户原始导出。
- 检查币种、千位符、小数点、百分比、时间范围和空值。
- 去重前保留父子 ASIN 关系；不要把父体销量与所有子体销量相加。
- `competitor_lookup` 的空白 `reviews` 保持 `MISSING`；评分数优先请求 `ratings`，必要时用 `asin_detail` 核对，不得把空白解析为 0。
- 按评分数/价格锁定核心组时，同步保存标价、Coupon 后价、标准化单件价、币种、星级、评分数、评分共享口径和快照日期；不同口径不能直接进入同一对标带。
- 将 `1K+`、`400+` 等区间值保留为区间，不伪造精确数。
- 将工具估算与 Amazon 可见事实分列，不在同一列混合。
- 对异常高销量、负毛利、极端评论新增或日期错误做第二来源交叉检查。
- 若下载文件包含与任务无关的账号或店铺私密字段，不读取、不引用并提醒用户另存最小化导出。

## 无法访问时的降级路径

依次尝试：用户提供的导出文件 → Amazon 公共页面 → 当前可访问的可靠第三方页面 → 明确的数据缺口。

登录、验证码、反爬或页面故障阻断时停止继续试探。继续完成商品、内容、VOC 与视觉分析，把销量、关键词或趋势结论标为 `UNKNOWN` 或低置信度；绝不以模型常识填数。
