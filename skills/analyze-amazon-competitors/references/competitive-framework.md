## 战场定义

先用一句话定义真正的竞争：

> 面向【人群】，在【触发场景】完成【任务】，以【价格/形态/购买逻辑】比较的【产品集合】。

不要仅因类目相同就视为直接竞品。先保留 `source_role`，再为每个 ASIN 独立标注一个 `primary_role` 和可选的 `roles[]`：

- `LEADER`：类目或核心词头部。
- `LAUNCH_PEER`：当前/目标评分数阶段、星级信任水平、标准化价格或资源更接近。
- `DIRECT_PRICE_FORM`：用途、形态、价格带、数量和购买逻辑直接相近。
- `NEW_ENTRANT`：近期上架且已出现可见需求。
- `DIFFERENTIATED_CHALLENGER`：新品、快速增长或差异化切入者。
- `ADJACENT_ALTERNATIVE`：完成同一任务的相邻替代方案。

`source_role` 只使用 `USER_SUPPLIED / UPSTREAM_SELECTED / RESEARCH_ADDED`。`ANCHOR / DIRECT / CHALLENGER / SUBSTITUTE` 是旧值，按 [benchmark-locking.md](benchmark-locking.md) 映射后不再出现在新报告。

核心叙事优先比较 4–8 个对象；只有数据规模研究才扩大。用户指定的 ASIN 不得静默丢弃，原始顺序始终保留。极速实战档按 [SKILL.md 的竞品研究分层规则](../SKILL.md#竞品研究分层) 选择研究深度，不把普通列表顺序视为排名；深度尽调档建立完整矩阵并另选核心组。不同角色分别总结，不计算误导性的全体平均值。

## 比较维度

### 产品与体验

材料、结构、核心性能、尺寸/重量、容量/数量、兼容性、配件、耐用性、使用步骤、清洁/维护、收纳、包装和故障模式。

### Offer 与价值

售价、Coupon、单位价格、套装、变体、保修/退换、配送、赠品、感知价值、潜在退货成本和快照所在的需求/价格阶段。

### 人群、场景与定位

目标人群、触发场景、核心任务、替代方案、标题承诺、价格心智、礼赠/专业/日用定位和教育成本。

### 搜索与流量

核心词、长尾意图、自然/广告/关联流量结构、关键词集中度、需求阶段与页面承诺的一致性。第三方词量只作估算；断货、促销和跨季节阶段可能扭曲排名或销量，必须保留反证。

### 内容与转化表达

主图识别、图片顺序、每图任务、手机端可读性、功能演示、尺寸/兼容、场景、对比、证据形式、视频、A+、品牌一致性和未回答异议。

### VOC 与信任

重复赞点、抱怨、严重度、发生场景、预期落差、退货诱因、Q&A 缺口、实拍、测试、认证、结构细节、品牌背书和评论护城河。

### 护城河与风险

品牌心智、评论规模、专利/外观、供应链、独家功能、价格战能力、自营优势、监管/认证、商标与复制风险。

为每个维度输出：`竞品事实 → 买家含义 → 可攻击性 → 证据 ID`。我方产品存在时，再输出 `我方状态与所需补证`。

竞品可见库存、配送和价格只作为当前 Offer 快照。不得据此推断其内部库存量、供应商产能、生产周期、运输路线或补货策略。`feasibility_speed` 只使用我方或上游可追溯的供应路线与能力证据；缺失时保持未知，不用竞品页面代填。

## VOC 地图

不要只列“优点/缺点”。把评论和 Q&A 转成：

| 主题 | 正/负 | 使用场景 | 触发条件 | 用户原始期待 | 实际结果 | 严重度 | 重复性 | ASIN/变体 | 证据 ID | 机会含义 |
|---|---|---|---|---|---|---|---|---|---|---|

严重度优先于出现次数：安全、损坏、无法使用、退货和兼容错误通常高于审美偏好。重复性只描述当前样本，不外推市场比例。

将“用户说的问题”与“推测的根因”分开。根因无法从结构、说明或多条证据确认时标为 `INFERRED`。

## 缺口分类

- **产品缺口**：需要改变材料、结构、性能、尺寸、质量控制或使用体验。
- **Offer 缺口**：可通过数量、配件、组合、包装、服务或价值架构解决。
- **表达缺口**：竞品可能做得到但未清楚证明；我方可通过更清晰的图片或证据抢位。
- **证据缺口**：有吸引力但尚无实测、认证、文件或可视化证明。
- **伪缺口/同质项**：用户价值弱、竞争者易复制、教育成本高、只靠降价或风险过高。

评论痛点不会自动成为我方优势。必须写出要实现的产品条件、验证方法和视觉证明。

## 攻防四区

- **重点进攻**：买家重要、竞品失守、我方能做到并能证明。
- **传播抢位**：产品差异不大，但竞品解释不清；以三秒可理解的图片先占心智。
- **必须守住**：买家高度重视且头部已做好的基础项；缺失会失去入场资格。
- **不参与竞争**：需求弱、成本过高、不可证明、侵权/合规风险大或对手护城河太深。

另列 `难以撼动的护城河`，例如强品牌、巨量评论、专利、Amazon 自营或不可持续低价。不要把护城河写成短期图片问题。

## 突破口评分

每个候选机会按 0–5 分：

| 字段 | 权重 | 5 分含义 |
|---|---:|---|
| `demand_strength` | 25% | 需求强、持续且有多个信号 |
| `competitor_gap` | 20% | 主要竞品重复失守或明显未表达 |
| `proof_strength` | 20% | 我方已具备且有强证据可证明 |
| `visual_clarity` | 15% | 手机端三秒内可理解并可拍/可画 |
| `commercial_impact` | 10% | 明显影响转化、溢价、退货或复购 |
| `feasibility_speed` | 10% | 实现快、成本合理、供应链可控 |

另填 `risk_penalty` 0–20，综合合规、IP、误导、质量与研发风险：

```text
Raw = 20 × (0.25D + 0.20G + 0.20P + 0.15V + 0.10B + 0.10F)
Adjusted = clamp(Raw - RiskPenalty, 0, 100)
```

使用当前技能目录下的 `scripts/score_breakthroughs.py` 统一计算；从任意工作目录运行时使用完整技能路径，不要假设当前目录就是技能目录。脚本输入：

```json
[
  {
    "id": "O1",
    "name": "示例机会",
    "demand_strength": 4,
    "competitor_gap": 4,
    "proof_strength": 3,
    "visual_clarity": 5,
    "commercial_impact": 4,
    "feasibility_speed": 3,
    "risk_penalty": 5,
    "evidence_confidence": "medium",
    "critical_fact_missing": false,
    "high_risk_claim_unmatched": false,
    "hard_blocker": false
  }
]
```

运行方式：

```bash
python3 <skill-directory>/scripts/score_breakthroughs.py --input <opportunities.json> --format markdown
```

决策阈值：`75+ 主攻候选`、`60–74.9 辅助候选`、`45–59.9 待验证`、`<45 降级`。脚本接受 `高/中/低/未知` 或 `high/medium/low/unknown` 置信度。出现以下任一情况时，无论得分多少都改为 `待验证` 或 `BLOCKED`：

- `proof_strength < 3`；
- `critical_fact_missing=true`：关键规格或我方能力未确认；
- `high_risk_claim_unmatched=true`：比较、医疗、安全、认证、环保或兼容性主张无匹配证据；
- `hard_blocker=true`：存在不可接受的合规/IP/产品责任红线。

三个布尔闸门字段都必须在每个候选中显式提供；脚本拒绝缺失字段，不能用省略来表示 `false`。Markdown 输出使用中文置信度与决策标签，JSON 输出保留规范化英文值，便于后续程序处理。

分数表达排序，不表达成功概率。单独报告证据置信度。

## 策略收敛

只选一个主打法，可加最多两个辅助打法：

- 细分人群或场景侧翼；
- 高频痛点消除；
- 可视化证据与信任抢位；
- 性能或体验升级；
- Offer、套装或价值架构重构；
- 设计、便携、收纳或礼赠；
- 风险逆转和购买前教育。

用以下格式表达：

> 对【目标人群】，在【场景/任务】下，以【主突破口】替代【竞品主要妥协】，并用【可验证证据】在首屏证明；同时守住【基础项】，主动放弃【不打方向】。

## 反证与停止条件

主动寻找：竞品近期修复、评论只来自旧版本、头部已覆盖该卖点、我方成本/性能无法实现、差异不可被买家感知、图片无法合法证明、需求只在极小场景或利润依赖不可持续低价。

出现明确侵权/禁售风险、关键体验无法达到、差异仅是换色/换词、或唯一打法是价格战时，停止把该方向列为主突破口。保留为风险或“不打什么”。
