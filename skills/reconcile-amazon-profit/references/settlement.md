# 结算与退款核销

`SETTLEMENT` 要求逐层核对：销售/订单范围 → 财务交易身份与状态 → 费用/退款 → 内部成本与库存归属 → Settlement 周期 → 实际打款。财务入账与银行到账日期可不同；留存、预留金、上期结转、跨期费用、税/币种转换分别桥接。打款是现金流校验，不是经营利润公式。Settlement 报告已生成、Finances 交易 ID 无重复或某类 `RELEASED` 已入账，均不能单独证明最终利润。

同一交易的授权、递延、释放、冲销、退款与调整要按可追溯身份及生命周期链接；一个经济事件只入账一次。对应 `DEFERRED/DEFERRED_RELEASED/RELEASED` 记录不能叠加；无法链接的记录单列待核。退款至少拆成销售收入冲回、退款/退货处理费、商品实体是否返回、返回可售或报废、平台赔偿/追索及其账期，不能把“退款数”等同实物退货数。广告报告花费、财务扣款和结算行用来源 ID 对账，选一个利润纳入位置。

为每条桥接列出定义与算式，例如：

- 交易残差 = 本期已纳入的逐笔财务净额 − 对应 Settlement 已识别交易净额；
- 打款残差 = Settlement 应付净额 ± 明示的跨期结转/预留/汇兑项目 − 实际到账净额；
- 成本残差 = 已审核可归属总成本 − 已分配至售出成本与期末存货/其他已识别去向之和。

仅在来源覆盖、身份映射、退款/费用状态、实际匹配成本和分摊闭环均核实，且残差为零或每项残差有凭证解释与明确期别时，标“最终已结算利润”。店铺总体对平不自动证明各SKU利润真实：仍使用模型均摊的SKU结果必须保留分摊方法及估计属性，不能改称逐SKU实际归属。仍有未知核心成本、未成熟交易或无凭证残差时维持部分复盘，写出差额及最小待补证据；不得用“其他调整”静默冲平。若用户只要指定期间的暂定复盘，不为获得最终标签无限等待异步报告。
