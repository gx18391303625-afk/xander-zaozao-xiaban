# Amazon 前台反向验证

前台验证用于回答两个问题：Amazon 当前怎样理解这个查询，以及以我方当前 Offer 进入时面对什么竞争。它不是流量或转化证明。

## 适用范围优先

下文关键词选择与十页深度服务于词库相关性/竞争验证。用户只要排名、同屏邻居或为广告诊断补证时，使用“排名与同屏取证”：服从指定词表、ASIN、地区、数据源和页数/调用限制；已有监控沿用其当前配置。若没有深度约定，记录一个与问题相称的有界范围；找到目标且取得所需邻居后即可停止，未找到则明确实际扫描深度。不将该结果称为完整 SERP 相关性验证或完整词库。

此模式只交付证据与简短结论，不启动大盘/竞品全量词源采集，不自动输出 Excel、重新分类词库或生成 Listing 交接。需要改词库角色时才回到主技能的产品事实、需求与分类门槛。

## 1. 浏览器与运行环境

- 用户明确要求使用已打开的 Chrome、无痕页、登录态或扩展时，使用 Chrome 控制能力并保持其现有会话。
- 不依赖现有 Chrome 状态时，可使用应用内浏览器。
- 记录站点域名、抓取时间、界面语言、配送地区/邮编（若可见）、登录/无痕状态和设备视图。
- 不静默改变配送地区、语言或筛选条件。地区不确定时把价格和库存解释为当前会话快照。
- 遇到验证码、反爬或登录阻断时停止重复刷新，记录 `FETCH_FAILED` 与已完成页数；不得绕过访问控制或补造页面。

## 2. 关键词选择

优先验证：

1. 准备进入 `CORE_VERIFIED` 的词；
2. 高流量但相关性或竞争有争议的词；
3. 直接竞品出现但大盘需求弱的词；
4. 产品强匹配但只有推断或 SERP 证据的功能长尾；
5. 可能进入错误意图、品牌/IP 隔离或不支持角色，但仍存在误判风险的短词。

同一近似家族不要机械扫描每个变体。先选有独立数据差异或意图差异的代表词；若 Amazon 纠错到另一个查询，记录原查询、纠正词和结果是否相同，再决定是否补扫。用户明确要求逐词验证时，以其指定清单为准，不得用词族合并省略。

**默认深度（用户没指定时）**：只验证拟进入 `CORE_VERIFIED` 的词和可能改变结论的争议词，每词看首页卡片。没做前台验证的次级候选词保持 `RELEVANT_NEEDS_VALIDATION`（不能标 `SECONDARY_VERIFIED`），在交付里列为“未前台验证”缺口，留给用户决定是否加深。用户要求完整建库或深度核验时，前台验证覆盖拟进入 `CORE_VERIFIED / SECONDARY_VERIFIED / RELEVANT_NEEDS_VALIDATION / LATER_STAGE_RELEVANT` 以及可能改变结论的争议词，按十页深度。任何深度都不对全部 RAW、明显不支持或已冻结词逐一扫描。没有浏览器/网页读取能力时，记为缺口而不是中断运行。最终列出主库词数、验证词数、每个验证词的选择原因、计划页和实扫页，避免把“每个纳入词扫十页”误解为“所有 RAW 词都扫十页”。

## 3. 页数规则

严格按用户要求：

- Amazon 显示或可继续到 10 页及以上：检查第 1–10 页；
- 总可见页数少于 10：检查全部可见页；
- 如果分页被无限滚动替代，以页面实际可辨识批次记录，最多覆盖等价前 10 页；
- 若 Amazon 只显示部分页且无法继续，记录 `visible_pages` 与 `planned_pages`，不得声称已全看。

先快速浏览所有要求页的搜索结果卡片。只有信息不足且会改变结论时才打开详情页。

## 4. 每页记录

为每个可见商品卡片尽量记录：

- 查询词、页码、页面内顺序、ASIN 或商品链接；
- Sponsored/Organic/其他推荐类型；
- 标题、品牌、可见主图形态；
- 标价、Coupon/折扣、Prime 价和可比到手价；
- 星级、评论数；
- 套装数量、形态和标题明确列出的关键属性；
- 与查询的关系：`DIRECT / CONDITIONAL / ADJACENT / IRRELEVANT / AMBIGUOUS`；
- 我方同形态/同套装：`YES / NO / UNKNOWN`；
- 明显污染原因；
- 是否为用户指定竞品或补充发现。

Sponsored 与 Organic 分开计数；搜索框上方品牌广告、视频位和普通商品卡片不要混为一个位置口径。

### 排名与同屏取证的附加规则

- 明确排名的统计单位：已确认普通自然卡片、广告模块内序号或页面内顺序，不混称“第几位”。跨页自然位累计使用实际已扫描卡片数，不预设固定每页数量；广告/推荐/不明模块不能默默计入自然位。
- 保存原始查询及纠错结果、目标子 ASIN、页面/模块、截图或页面来源 ID、采样时间/时区和会话条件；字段无法取得时保持未知。`observed_at` 不被文件更新时间或后续汇报日期覆盖。
- 用 `OBSERVED / NOT_FOUND_WITHIN_DEPTH / FETCH_FAILED / NOT_SAMPLED` 区分已见、有限深度内未见、失败和未采；单次未见广告不能推断零投放，未见自然卡片不能断言没有收录。
- 邻居保留与我方的页面/模块关系，区分自然和广告。只能从同次页面证据取“当时同屏”；将历史排名与今天竞品价格拼接只算背景，不算历史邻居复原。
- 明确“前后邻居”指自然序列相邻还是视觉相邻；两者不同时分别标注。页/模块边缘、未加载或身份未知时保留缺口，不以我方名次 ±1 推定未观察的卡片或 ASIN。
- 比较变化时核对查询、对象、地区、设备、计数方法与可比会话条件，展示两次源时间；新对象或方法变化建新基线。数据可比时按任务要求显示 ↑/↓，不继承旧日报“不显示变化”规则到所有任务。
- 交接的是排名/页面证据，不是广告点击归因；保留词库角色和稳定 ID。对接 `$build-amazon-advertising-strategy` 时不要按 campaign ID 将位置表现摊到某个词或邻居 ASIN。
- 不点击 Sponsored 广告验证身份；需要后补产品信息时使用确认 ASIN 的普通商品链接，后补快照与同屏原值分开。

## 5. 相关性判定

以购买意图而不是单个词命中判定：

- `DIRECT`：核心产品类型、形态、数量/兼容关系与查询一致；
- `CONDITIONAL`：同类但套装、尺寸、接口、场景或关键属性只部分一致；
- `ADJACENT`：解决相近问题但产品形态或购买逻辑不同；
- `IRRELEVANT`：不满足核心意图；
- `AMBIGUOUS`：卡片信息不足。

不要仅凭标题包含关键词就判 `DIRECT`。对套装、容量、认证、温度、续航、材质等无法从卡片确认的属性标 `UNKNOWN`，必要时再开详情页。

## 6. 详情页升级条件

仅在下列情况打开详情页：

- 结果卡片无法确认是否同形态/同套装；
- 一个低价或低评论商品可能实质改变竞争背景判断；
- 标题中的功能/规格可能只是营销措辞；
- 需要核对变体、Coupon 后价格或关键兼容关系；
- 需要确认用户指定竞品是否为当前展示子体。

记录打开原因与结论。不要为了“深看”而逐个打开所有结果。

## 7. 汇总指标

首页和全部已扫描页分别输出：

- 结果卡片数、Sponsored 数和 Organic 数；
- `DIRECT` 数与直相关率；
- 我方同形态/同套装率；
- 标题明确匹配关键属性的比例；
- `ADJACENT + IRRELEVANT` 污染率和主要污染类型；
- 可比商品到手价的中位数、四分位和范围；
- 可比商品评论数的中位数、四分位和范围；
- 用户指定 ASIN 出现页与位置；
- 重复品牌/ASIN、头部集中和新品/低评论商品信号；
- 纠错、搜索建议或 Amazon 解释文案。

分母必须写清。无法确认的卡片保留在 `AMBIGUOUS`，不要为了得到好看的相关率强行归类。

## 8. 竞争解释

至少回答：

- 查询是否主要购买我方这种产品，而不是替代品或错误形态；
- 我方的售价按同套装/同数量比较是折价、同带还是溢价；
- 首页评论门槛与全深度评论分布有多大差异；
- 页面是否被强品牌、巨量评论或密集广告控制；
- 我方差异在标题/主图卡片层是否能解释价格；
- 当前更适合 `CORE_VERIFIED`、`SECONDARY_VERIFIED`、`RELEVANT_NEEDS_VALIDATION`、`LATER_STAGE_RELEVANT`、`INDEXING_CANDIDATE` 或其他隔离/排除角色。

如果只有深页出现低评论可比商品，表述为“深页存在同阶段供给”，不能写“容易进入首页”。

## 9. 证据边界

- SERP 相关性不证明搜索量。
- Sponsored 密度不直接等于 CPC。
- 结果数量不等于真实竞争商品数。
- 当前页价格不等于历史稳定成交价。
- 页面卡片标题不证明功能真实或认证有效。
- 单次无痕/登录会话不代表所有地区和时间；结论必须带快照日期。

把前台结论与大盘需求、竞品流量和产品门禁合并后再给词库角色，不能单独用 SERP 落锤“核心词”。前台验证只提供研究证据，不生成广告活动、匹配方式、出价、预算或否定规则。
