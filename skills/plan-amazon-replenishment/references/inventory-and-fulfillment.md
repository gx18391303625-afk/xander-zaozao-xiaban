# 库存身份、履约状态与执行边界

## 库存先去重再计算

每个库存/货件行保留：账户、站点、SKU/FNSKU/ASIN、变体及套装、地点、批次/采购单/货件/运输ID、数量及单位、原状态、观察时间、来源、已包含/重叠关系。未知身份不强行合并，冲突状态并列待核。

平台字段定义由当前API/导出说明确定，不能只看名字相减。例如FBA fulfillable=100、reserved=20且二者互斥时，当前可售是100，不是80；若总库存120包含reserved20，则可以推得100。卖家另留的10件只有确实包含在这100件且不与其它预留重叠时才扣除。安全库存是运营缓冲，不改变平台物理可售事实。

每批库存沿时间保留状态变更，不能把前一状态与后一状态相加。常见状态链不是所有平台的固定枚举：计划→生产/备妥→仓库接收→已交承运商/运输→送达FBA→接收处理中→可售。各状态必须有对应证据：

| 证据 | 能证明 | 不能证明 |
|---|---|---|
| 已创建采购/货件或打印标签 | 计划/记录存在 | 已生产、已发运 |
| 工厂备妥/装箱记录 | 已准备数量 | 承运商已提走 |
| 承运商提货、运输追踪 | 对应运输事件 | Amazon已接收可售 |
| 签收或Delivered | 对应地点交付 | 全量接收、无短少或已上架 |
| FBA receiving/checked-in | 接收流程状态 | 全部fulfillable |
| 对应SKU当前fulfillable | 当时可售数量 | 未来库存保证 |

海外仓已出库但账面尚未扣除、Amazon已创建但尚未收到的同一批货，只计一个物理存量；用运输ID/批次做桥接，不以状态名猜去重。部分收货拆成互斥数量；已收到部分不能又包含在未到余量。取消、丢失、破损、不可售、退货待检单列；退款不代表可售退货回仓。

## 收货与差异

按SKU/货件对平计划、实际发运、签收、已接收、可售、不可售和待核数量，区分“尚未接收”与“确证丢失”。平台货件关闭不保证无差异。只在当前政策、申请窗口和证据满足时提出调查/索赔路径，不自动提交或承诺赔偿。

体积/重量采用实际箱规和承运口径；不能用产品净重充当毛重，也不猜带电货物运输资格。涉及电池、危险品、进口、标签、包装限制、费用或平台期限时核验当前官方规则；供应商承诺和平台许可分开。

## 授权、操作和回读

只读查询、计算、装箱清单草稿不等于订舱或发货。采购、付款、订舱、对外发送、创建/更改/取消货件、调拨、销毁或库存修正都须当次明确授权；现成的精确批准不重复询问。

执行前绑定准确账户、对象ID、SKU/件箱数量、目的地、运输/承运选择、费用币种与上限、日期和约束，保存审批依据及执行前状态。地址或费用等关键变化超出批准范围时停在受影响动作，不擅自替代。发现不可恢复或高成本影响而原批准未覆盖，先集中确认。

先检查当前工具是否实际支持该操作、权限和目标字段，不能把浏览器页面可见或接口文档存在说成已具备可执行能力。不支持时交可审阅资料/人工步骤，不宣称已提交。

写入后保存平台返回ID、准确数量/目的地/费用及状态，重新读取对应对象核验。响应超时或结果不确定时先查现有对象/幂等标识，不重复创建、扣款或订舱。每个动作一次合理替代查询仍不能确认时，交待核状态和最小人工核实项。授权创建货件不包含授权付款或取消其它货件。

## 按时间投影库存

投影起点必须明确是一天开始还是结束。同日供给与需求的先后用已知可售时点；仅有日期时，保守使用日末入库、下一日可供需求，或披露其它假设，不能靠同日总量掩盖日内空窗。

未来供给只在有身份、数量和预计可售日期的节点加入情景；低/高不确定到货分别做敏感性分析。未知到货不计入确定保障，但保留在未定供给表。已经在起点库存中的接收批次不能再次作为未来到货加入。

逐日物理余额不得靠未履行订单变成负库存：可满足需求=min(可用物理库存,当日需求)，失销量/待履约需求单列；缺货时流失的销量不能在之后到货时再次扣减。若确有backorder则单独保留欠单并约束未来供给。另可用不截零的累计供需差显示缺口，但必须叫累计缺口，不能叫实际库存。建议量按补货到达后的可销售需求定，不为已流失历史需求补货。
