# 季节与跨模块决策复盘

当季节变化、剩余销售窗口，或广告、价格促销、库存现金共同影响下一步时使用。窄问题只取相关部分；不因本参考新增一套阶段、完整策略包要求或固定复盘周期。它是一份人工判断与交接规则，现有工具不会自动计算共同门禁，也不会据此自动调价、投放、停投或采购。

## 先把三类判断分开

| 判断 | 复用的证据与字段 | 不能代替什么 |
|---|---|---|
| 市场需求走到哪里 | `seasonality_context` 的有日期观察；`demand_calendar` 的需求情景和销售窗口；保留来源周期、粒度、置信度及刷新时间 | 旺季、排名或搜索热度不能证明我方链接已经转化稳定；计划中的月份不是当前阶段 |
| 我方链接验证到哪里 | 有观察证据的 `current_stage`；目标/query 的相关流量、订单、归因成熟度和经济线；可取得时补充 SQP 份额及同屏证据；现有 `phase_plan` 仅提供待核对门槛 | 阶段计划不能证明已经达标；点击量、单日出单、自然位或份额改善不能单独证明可放大，更不能证明广告造成自然增长 |
| 库存现金能承受到哪里 | 现有 `inventory`、补货路线/可售日期、利润底线、策略/阶段支出上限、已批准学习损失和可用资金 | 入仓中库存不是当前可售量；日预算不是累计损失上限；市场增长不能补足现金或库存缺口 |

沿用 [广告运营上下文](../../build-amazon-advertising-strategy/references/operating-context-and-replenishment.md)、[链接成熟度](../../build-amazon-advertising-strategy/references/keyword-share-and-link-maturity.md) 和 [补货销售窗口](../../plan-amazon-replenishment/references/demand-and-quantity.md)。已有 `operating_context` 保留原 ID、哈希和内容；新观察另记带时间的快照或记录，不为贴合结论改写信封。没有阶段证据时保留未知，不按月份自动进入成长、成熟或衰退阶段。

## 让同一次决策共用门禁

- **放大：所有适用条件同时满足。** 本次需求与可比窗口、目标/链接验证、归因与数据充分性、利润与增量表现、库存现金及剩余时间都支持这个具体动作，才提出有范围的放大；每项标明已满足、未满足、未知或有依据的不适用。市场门禁不要求需求一定上升，尾季仍盈利、周转与窗口适配的已验证投放也可以继续评估增投。任何一项变好都不能抵消其他硬边界。
- **硬边界优先。** 资格/合规失效，达到已批准的支出或损失上限，触及库存/现金边界，或批准范围失效时，优先停止相应新增暴露、保持待核状态或提出撤回。若当前活动仍会继续消耗，不加预算不等于止损；明确需要执行的限制/暂停、已有授权及尚未止住的风险，未执行并核验前不得宣称已经止损。归因尚未成熟不是继续突破额度的理由；未知结果先核验，不重复提交。先明确受影响对象，不机械暂停整个账户。
- **未知只能支持有界学习，不能冒充验证。** 明确要回答的问题、能获得的证据、最大支出/损失、停止条件和可判读时间；既有资格及其他硬门禁仍须满足。证据不足不能授权放大，也不要求把所有盈利中的原有投放一概停掉。
- **把时间可行性写进判断。** 分别写样本积累、归因回填、报表可得与复核时间，按实际时序估算最早可判读时点，避免重复相加。与有证据的剩余有效销售窗口和最迟行动时点比较；窗口不足时缩小问题、缩小暴露、保持已验证方案或不启动这次试验。日期未知则列缺口或做明确情景，不借用别的产品季节。最后经济到仓日与销售窗口结束日是不同约束。
- **区分三个动作。** 停止新增暴露是不再增加该风险；结束试验是关闭本次问题并记录已知/未知结果；恢复基准是把具体配置恢复到有快照的原值。三者可能需要不同操作和授权。恢复前确认原值仍适用于当前价格、资格和库存，不能盲目回放历史配置。

继续使用既有新品/老品阶段，不增设“季节总阶段”。已有结构化广告包可把共同条件写入 `decision_rules.condition / minimum_evidence / financial_ceiling / proposed_action / rollback_condition`，由 `phase_plan.entry_gates / exit_gates / rollback_conditions` 引用规则 ID。`source_snapshot_ids` 仍只引用合同允许的绩效快照；市场/上下文证据保留其原引用，不塞进该字段冒充广告绩效。现有校验器不会解释这些文字并自动判定联合条件成立。

## 清货时重新写清目标与账

清货仍需明确优先目标：期望清货速度、截止时间、净现金回收要求，以及允许留下多少库存、如何处置。没有明确接受的新损失或残量约束时，不擅自降低原利润底线，也不以“清货”概括无限折价或加广告。

每次考虑改价、Coupon、Deal 或广告暴露，按有效成交价重算折扣、促销费用、平台/履约费用、退货退款和广告支出，分别列贡献利润与预计净现金回收。区分已付采购成本、未来增量支出和会计利润；收入增长不等于现金回收改善。销售收入、预计净回款金额、实际可支用回款时间分别记录；结算延迟、资金预留或支出到期造成的资金缺口，不能用尚未可支用的销售收入抵消。销量情景必须来自适用窗口，不能用旺季峰值保证尾季售罄。只剩销量速度达标而现金、损失或允许残量不达标时，仍是目标冲突，应明确交由用户取舍。

利润与费用口径交 `reconcile-amazon-profit`，可售量、补货和最后经济窗口交 `plan-amazon-replenishment`，广告经济线与具体投放动作交 `build-amazon-advertising-strategy`。价格和促销由总协调按实际支持能力组织精确提案或人工交接；广告授权不包含改价、促销或采购。

## 简洁复盘卡

按本次问题填写，已有材料直接引用；无关项写明不适用。不要为填卡强行补造数字。

| 项目 | 本次记录 |
|---|---|
| 范围与问题 | 账户、站点、SKU/ASIN/变体、币种、时区；这次只判断什么 |
| 来源与截止 | 证据 ID/路径、实际覆盖期、获取时间、完整性；当前观察与计划分开；销售截止/最迟行动日期及其依据 |
| 三类证据 | 市场观察；链接/目标已验证与待验证项；可售库存、可支用资金及回款/付款时间、损失边界；各自未知项 |
| 基准与可比性 | 原配置/有效价格/促销快照、比较窗口、归因成熟度；同期价格、内容、库存或市场变化；无法分辨影响则标记混杂 |
| 测量与阈值 | 测什么、分子分母/单位、最低有效证据、阈值来自用户约束、经济线、可比实绩还是待验证假设；不用帖子里的固定数值代替 |
| 动作范围 | 具体对象、原值/拟改值、主要变量、最大新增支出/损失；是否已具备该范围的授权 |
| 放大/停止/撤回 | 各条件与当前结果；硬边界优先；分别写停止新增暴露、结束试验、恢复基准的触发与对象 |
| 时间与责任 | 起点、最早可判读时点、最迟行动时点、下一次复核触发；负责模块及缺口负责人 |
| 清货项（适用时） | 速度目标、现金回收要求、允许残量/处置、价格促销及费用重算、仍冲突的目标 |

这张卡不是授权凭证，也不是机器执行协议。动作由对应模块生成当前精确提案，按 [写入安全](write-safety.md) 核对授权、开关、实际执行与独立回读。规则成立不等于已经操作，计划中的撤回也不等于已恢复。

## 五个冲突例

1. **市场开始上升，链接尚无可判读订单证据。** 保留市场判断；只在硬门禁与批准额度内验证流量/相关性或转化问题，不直接进入放大。
2. **链接已有稳定盈利证据，但尾季剩余窗口短于新试验判读时间。** 可以继续评估已验证投放的当期贡献；新试验缩小问题或不启动，不因阶段名称自动清空投放。
3. **广告成本较高，关键词位置同时改善。** 保留相关观察，核对归因、利润及已批准学习额度；排名改善不能豁免止损，也不能替代增量效果验证。
4. **转化与利润达标，但补货晚到或现金不足。** 库存现金边界优先，提出限制相应新增暴露并交补货/利润模块；尚未可售的到货不能用来放行当下扩量。
5. **折价能加快售出，但扣除促销与广告费用后现金回收不足。** 同时展示速度、净回收和预计残量；重新比较价格/促销/广告组合，由用户处理仍存在的目标冲突，不只报告售出件数。

## 留下可接续的记录

复用现有 `xander_archive_note` 保存本次范围、来源/日期、门禁判断、决定、未决缺口、负责模块和复核触发；记录实际执行与回读时，区分提案、提交和已核验结果。用户确认的新成本或底线按 [店铺档案](business-context.md) 的事实写入规则处理。

下次仅复用确实取得且适用的历史记录；从当前可读档案、用户提供材料和实际可用日志找基准。没有找到原配置、阈值依据或旧决策，就标记历史缺口，不补造、不承诺自动找回，也不把旧记录当成当前账户状态。复核时间写入 note 不会自动创建监控或执行任务；持续监控需另按用户要求安排。
