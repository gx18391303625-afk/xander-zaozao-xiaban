# 官方接口优先，紫鸟兜底

适用：用户要完成的亚马逊操作，本插件的官方接口做不到（开关面板里显示“规划中”，或官方根本没有接口）。

## 先确认真的需要兜底

1. 用 `xander_switches` 看这类操作有没有官方实现。有就走官方。
2. 没有实现：说明原因，给用户两个选择——(a) 我给你一份精确的手动操作清单，你自己在后台点；(b) 用紫鸟让我代点（需要你打开“紫鸟控制”开关）。用户选 (b) 才继续。
3. 用 `xander_ziniao_status` 确认已配置、能连上、开关已开。开关是关的：请用户在 `xander panel` 打开，你不能代开。

## 操作流程

1. `xander_ziniao_snapshot`（只读）打开对应店铺、跳到功能页，核对卖家、站点、品牌、商品身份和页面上的实际字段。
2. 收齐下表需要的字段，写成精确提案：`xander_prepare_change`，op=`ziniao.control`，带 `browserId`、`description`（要达成什么）、`steps`（goto/click/type/wait/press，只允许亚马逊后台网址）。selector 要来自刚读到的页面，不能猜。
3. 把提案给用户看，取得对这一份的明确批准后 `xander_execute_change`。
4. 执行后再 `xander_ziniao_snapshot` 打开详情页，逐项核对批准的字段和状态；能用官方接口回读的（比如 Listing）也用接口回读。
5. 结果不明时先查原对象，**不要换渠道重复提交**。处理中、已排期、审核通过、买家可见要分别报告。

## 各类操作要先收齐的字段

| 操作 | 精确提案必须包含 |
| --- | --- |
| 优惠券 Coupon | ASIN/SKU/变体、金额或百分比、开始/结束时间与时区、预算、实际费用、目标人群、每客限制、叠加规则、资格 |
| 秒杀 Lightning/Best Deal | 可报名的商品和变体、类型、后台可选的日期时段、促销价、数量、费用、资格与审核状态 |
| 买 X 赠 Y / BOGO | 购买商品集合与门槛、受益商品与数量、免费/固定价/折扣、预算、起止时间与时区、优惠码、每客限制、叠加/排他、展示条件 |
| Creator Connections | 品牌资格、计划名称和说明、ASIN 集合、佣金比例、预算、起止时间、页面显示的条款和费用 |

## 注意

- 新建向导一打开就自动保存草稿的，先停在入口，等提案批准后再进。
- 页面上的字段、费用或范围和批准的不一样：更新提案、重新批准。
- A/B 实验（Manage Your Experiments）由用户自己操作。
- 紫鸟是模拟人工点击，页面改版会失败；失败时如实报告，不要反复乱点。
