## 已核验

- `node --test test/*.test.js`：**586 项通过，0 失败**。

- `npm pack --dry-run --json` 确认包含 Client、Host 设置桥、补丁、中文/英文元数据与原有图标等资源。

- 未对全部窄屏、屏幕阅读器或其他 DSH 版本/远程部署作兼容承诺。
- 原完整网页启动、重复使用和卸载清理有隔离测试；未为验收向模型输出原网页的一次性口令。
- 浏览器认证、browserPeer 与 CSRF 门禁不防御同源恶意脚本、浏览器自动化或同机任意代码；不注册开关写工具也不意味着能阻止任意本机程序。AI 不得代用户拨动开关的规则保持不变。

## 已撤回的六类折叠方案（2026-11-17，未发布开发历史）

> 用户随后明确需求是减少实际权限开关，最终指定「广告、链接、FBA 货件、紫鸟」四总权限。六类折叠方案已被取代；以下保留该阶段的历史证据，不代表当前界面，也不能用其中 611 项旧回归或旧截图冒充四总权限改造的验收结果。

- 按用户确认方案重组为六类，31 项分别为 15 / 8 / 3 / 2 / 2 / 1；SP 为日常 10 项、创建与预算策略 5 项，品牌广告分 SB 4 项与 SD 4 项。默认全部折叠，搜索命中自动展开且另列匹配数，清除后恢复浏览折叠。
- 分类与折叠状态为纯 Client 展示模型，未知新增能力保留在“其他”；没有分类总开关，原逐项写入、鉴权、CSRF、冲突处理及原网页均未改变。
- 新增 19 项测试只截取并执行生产脚本中标记的纯模型，不执行 React、模拟 DOM 或制作替代页面；覆盖唯一归类、严格计数、搜索字段、未知项与折叠状态。最终全套 611 项 Node 回归、语法、版本一致性与 diff 空白检查通过。
- 真实运行的 Desktop 已呈现深色默认分类卡、完整开启计数和“共 6 类”提示；首屏其余分类可向下浏览。截图中的 Host 版本仍为此前已加载的 2.9.2，不能据此宣称 Host 已重载或新版已公开发布。
- 独立 UI/UX 审查未发现 P0/P1；已采纳分类总数提示、零结果搜索 live status 和清除搜索回焦。空反馈不占位，保留原触控尺寸和主题变量。
- 证据限制：当前桌面自动化对网页按钮与标准搜索框的输入未取得可靠响应，真实展开、搜索、清除恢复、浅色、窄屏和读屏操作不列为实测通过项。浏览器访问现有 GUI 提示需要认证，未寻找凭证、修复环境或使用 mock UI 补证。
- 此已撤回阶段只调整本地源码，不拨动真实开关；当时未升级包版本、未提交推送或另发 Release。

## v2.11.0 四总权限：发布前开发验收历史

> 以下记录发生在四总权限开发完成、升版发布准备之前，保留当时的测试数量、2.10.0 源码版本及旧 Host 缓存现象。它不是 v2.11.0 发行流水线成功或新版本已在真实 GUI 冷加载通过的证明；当前版本的使用与升级步骤见[四总权限说明](<four-master-switches.md>)。

- 最终范围为「广告」`ads.manage`（23 项，含 SP 账户总预算）、「链接」`listing.manage`（6 项）、「FBA 货件」`fba.inbound`、「紫鸟」`ziniao.control`。细分操作 ID 留作精确提案、既有状态兼容与审计；不是四个折叠分类里继续提供 31 个子开关。范围见[四总权限说明](<four-master-switches.md>)。
- 该阶段的验收合同：新目录默认关；读取不写；旧组内有开有关时显示“部分开启”且 `on: null`，不当成全关或自动扩权；用户明确统一才一次保存本组，不改变其他总权限。
- 该阶段要求核验 DSH、原面板与 CLI 的公开写入口只接受四总权限，旧细分命令不能自动提升成整组授权；无一键全开，保留用户主动 `all-off` 紧急停权。精确提案、哈希、审批、单次执行、费用另批与未知结果只核验等边界不得削弱。

- **旧页面兼容与独立审查：** 两 Host 强制 `permissionModel: 'masters-v1'`，防止旧细开关 Client 拿到新 CSRF／revision 后直接单击整组授权。两 Host 的合法身份、最新版本下共 88 次缺失／错误模型负向 POST 均拒绝且无权限／审计写入。独立安全及 UX 审查发现的兼容协议和 DSH 确认焦点两项 P1 已在源码与隔离测试层闭环；DSH 使用可访问内联确认区，原网页使用原生 dialog。原子文件替换不等于跨进程 CAS，既存竞态边界见[四总权限说明](<four-master-switches.md#已有权限如何保留>)。
