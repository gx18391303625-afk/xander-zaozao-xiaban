# 2.5：经营诊断、行动卡与实验复盘

本次把已有六模块的证据衔接成可追溯闭环，**没有增加自动投放、自动调价或无人审批**。不新增运营模块，不改真实店铺、令牌、用户开关或既有提案协议。

## 可以直接这样说

> “看看这个 ASIN 当前最值得做哪三件事，哪件事暂时别动，并说明证据。”
>
> “把这次诊断和行动计划存下来，写清最多能花多少、什么情况停止、什么时候才适合复盘。”
>
> “读上次的实验卡，分别说清实际改了什么、后来表现怎样、还有哪些解释不能排除。”

AI先从档案和相关模块取证，不要求用户手填大表。单指标、单字段等窄问题仍用原工具，不强制跑完整诊断。

## 本次新增

### 1. 单 SKU/ASIN 经营诊断

明确店铺、站点、对象、期间、时区、币种和本次经营目标。目标分为验证需求、扩大已验证销量、稳定盈利、清库存；需要用户确认，**不会按上架月龄自动切阶段**。

每个动作都有具体对象、负责模块、理由和证据门禁。最多选三项进入人工复核，其余保留暂不动或缺证原因；没有合格动作时不强凑三件事。

### 2. 证据门禁

- 区分事实、推断、估算、模拟与未知；缺失不是0。
- 检查店铺、站点、币种、对象、日期窗口是否一致；非SKU/ASIN动作核对具体活动/广告组等对象。
- 检查报告覆盖、分页、归因状态与取数时间；未来“事实”、漏分页和部分数据不能支持放行。绩效指标必须明确是否已隔离到本商品；共享广告组聚合、未说明归属不能冒充单ASIN样本。
- 经营动作需经济性、资格；扩量还需库存现金、样本归因和需求窗口。验证需求也需明确的学习支出/损失边界，不能因为样本少就无限试。
- **2点击1单不能因50%转化率而放量；活动A不能借活动B的成熟样本放量。** 不内置“20/30点击就足够”的固定经验阈值。
- 存在未排除的硬止损风险时，先阻断扩量和新增需求验证投入并交人工核对；不会一刀切禁止可能降低库存风险的清货计划，但清货仍需经济、资格与库存现金门禁。工具不会自行暂停广告，不能宣称已经止损。
- 即使根范围只给SKU，同店铺站点下该SKU出现互相冲突的ASIN映射也不能放行；合法的同ASIN多SKU不因此误伤。需求验证动作不能绕过当前已确认的经营目标。

通过只表示“按所供证据规则可进入人工复核”。工具不会联网认证来源，不证明阈值统计合理，不把填完表当审计完成。

### 3. 不可覆盖的诊断与行动卡

保存诊断时重新计算，不接受客户端塞入的伪造放行结果。实验必须绑定已有诊断、其中的具体动作和完全相同范围，记录假设、主要变量、基准、对照、支出/损失上限、停止条件和最早复盘日期。

实验保存的是诊断中**评估后的动作与门禁**，原始输入另存为rawAction；不会把调用方原先声称的“满足”重新当成通过。状态明确是诊断保存时的快照，未按当前数据复评。旧实验缺评估快照时，读取按未知展示，不覆盖旧记录。

计划上限不是新授权、平台熔断或自动监控。可选提案ID仅保存为**未核实引用**，不证明存在、属于本对象或已执行。

### 4. 追加式实验复盘

不覆盖早期记录，分开保存：

| 内容 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 平台执行回读声明 | 调用方报告查到了什么，可带具体来源 | 账本本身未重新核验平台，也不证明经营改善 |
| 描述式业务结果 | 给定观察期与报告覆盖下发生了什么 | 前后变化不等于因果增量 |
| 归因、对照和混杂 | 哪些解释仍未排除、何时值得复核 | 不能凭填写“verified”制造因果证明 |

未来观察日期拒绝；观察期未满、报告尚未覆盖、归因未知、无对照或混杂要明确保留。复盘决定只是记录，**停止、扩量和恢复原值仍需新的当前精确提案及批准**。

## 使用入口

| 工具 | 用途 |
|---|---|
| `xander_diagnose_asin` | 只读评估所供模块证据，不保存 |
| `xander_save_diagnostic` | 重新评估并保存不可覆盖诊断快照 |
| `xander_diagnostics` | 按店铺站点list/get，支持SKU/ASIN过滤 |
| `xander_experiment_create` | 创建绑定诊断动作的本地实验计划 |
| `xander_experiment_review` | 追加描述式复盘，不执行业务动作 |
| `xander_experiments` | list返回最新复盘摘要；get按reviewOffset/reviewLimit取历史，每页默认20、最多100条，按nextReviewOffset续读，不把一页当全部历史 |

开关面板新增**经营诊断与行动复盘**只读区，每类展示最近3条摘要。没有自动执行按钮，也没有为了新功能新增写开关。历史可能过期，下一次仍需取得当前证据；读取失败不等于没有问题。

数据保存在原本机档案数据库的独立表，旧事实、决策和提案不覆盖。只读查看不会为旧安装自动创建诊断表；首次保存时增加独立表。现有整库备份包含这些记录。大工具输出保存本机导出文件并显式提示，不能只看开头下结论。

## 升级与能力边界

- 本地源码版本为2.5.0；四处插件版本与MCP/CLI/面板统一。已经运行的MCP进程不会自动热加载新代码，需在宿主中重新连接/重启Xander。面板也需从新版本重新打开。
- **GitHub仓库更新不等于npm发布或所有宿主缓存已更新。** 使用缓存安装的宿主仍需更新对应安装并重新连接；不擅自重启宿主或结束进行中的提案。
- 不增加Amazon业务写入端点，不修改账户设置、密钥、写开关或原有安全上限。
- 不自动安排提醒、轮询取数或持续监控；最早复盘日期仅为记录。
- 不新增视频生成、多平台投放、AMC受众激活/付费订阅或无人驾驶调预算。
- 输入事实真实性、对照设计和阈值合理性仍须由各负责模块与用户判断。真实店铺业务效果尚未在本次更新中验证。
